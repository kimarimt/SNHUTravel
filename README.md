## User Requirements
User specifications and requirements can be interpreted as features necessary to provide value to the end users. These requirements can by converted into user stories which are clear, concise explanations of a software feature or project requirements written from the user's perspective. The standard format of user stories is "As a (user/persona) I want (specific action) so that (value is achieved). User stories promote conversations between the Scrum Team to clarify any addtional details, edge cases, and business rules.

## Software Development Approach
Agile Software Development is an iterative process in which program are developed small, incremental cycles called Sprints rather than building the entire product. This is accomplished through phases such as requirements planning, analysis, design, implementation, testing, deployment, and maintenanace. I would like to incorporate an online tool like Jira in order to standardized the development process.

## Team Asset
I believe that being a good team member in software development is being open and transparent even when the situation is not in your favor. Building software is not going to a smooth process all of the time and there will be disagreements. It important for the team for each member to be upfront with their mistakes and disagreements and handle them in professional way. This will help to improve the team's performance overall.
